# Ghi Sổ Phase 1–3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Offline-first PWA for personal expenses + friend debt ledger, through Phase 3 of the spec (MVP, quick input parser, insights & reminders). Sync (Phase 4) is out of scope, but the data model is sync-ready.

**Architecture:** Vite + React SPA, MVVM: pure `domain/` logic, Dexie repositories in `data/` injected via `RepositoryProvider`, one ViewModel hook per screen in `features/*/viewmodels`, dumb views. Layer boundaries enforced by ESLint `no-restricted-imports`.

**Tech Stack:** Vite, React 19, TypeScript strict, Tailwind v4, shadcn/ui (Drawer = vaul), React Router 7, Dexie 4 + dexie-react-hooks, vite-plugin-pwa, Recharts, date-fns, zod, i18next + react-i18next, Vitest + fast-check + @testing-library/react + fake-indexeddb, Playwright (WebKit). Package manager: pnpm.

**Spec:** `docs/SPEC.md`

## Global Constraints

- Money = integer VND. Display `Intl.NumberFormat('vi-VN', { style: 'currency', currency: 'VND' })` → `35.000 ₫` (both languages).
- `date` = `YYYY-MM-DD`; `createdAt/updatedAt/deletedAt` = full ISO. IDs = `crypto.randomUUID()`.
- Every write sets `updatedAt = nextUpdatedAt(prev)` = `max(now, prev + 1ms)` (spec 9.3).
- Delete = soft delete (`deletedAt` + `updatedAt`). Every repository read filters `deletedAt === null`.
- No unique index on `friends.name`; uniqueness (case/diacritic-insensitive, among non-deleted) enforced in repository.
- Code, identifiers, comments: English only. All UI text via i18n keys, languages `vi` and `en`; initial language from `navigator.language` (`vi*` → vi, else en), user override saved in `meta.language`.
- Mobile-first: viewport 375×667 … 430×932, touch targets ≥ 44×44, input font-size ≥ 16px, `min-h-dvh` (never `100vh`), safe-area insets, `touch-action: manipulation`, `overscroll-behavior: none` on body, forms/confirms in bottom sheet (`Drawer`), `tabular-nums` on amounts, truncate notes not amounts, dark mode via `prefers-color-scheme`, respect `prefers-reduced-motion`.
- Views never import `@/data/*`, `dexie`, `dexie-react-hooks`, or `@/domain/*` except `@/domain/types`. `domain/**` never imports `react`, `dexie`, `@/data/*`, `@/features/*`, i18n.
- No global state library. Context only for DI (repositories, settings).
- Each screen: loading skeleton, empty state, error state.

## Decisions taken (spec was silent / user answered)

- Parser: more than one amount token → `ParseError` `multipleAmounts`.
- Split rounding: per-friend share = `floor(amount / parts / 1000) * 1000`; remainder always goes to me, **including `cho` mode** (so `grab 50k cho @A @B @C` → 16k each, myShare 2k). Per-friend share 0 → error `amountTooSmall`.
- Mention token `@xyz` matches friend whose `normalize(name)` with spaces removed equals `normalize(xyz)`.
- `dd/mm` → current year.
- Reminder template placeholders: `{name}`, `{items}`, `{total}`. Stored in `meta.reminderTemplate`; empty → default from i18n.
- Parser keywords (`cho`, `hqua`, `hôm qua`) stay Vietnamese only (spec syntax); parser error codes translated in UI.
- ViewModel tests inject the Dexie repositories over `fake-indexeddb` (fresh DB per test) so `useLiveQuery` reactivity is real.
- Not done here: Vercel deploy, real-iPhone manual checklist (needs user account/device).

## Review Focus

1. Amount strings like `1.500` vs `1.5tr` vs `35.000` vs `2tr5` — dot as thousand separator vs decimal (only decimal when followed by `k`/`tr`). Test in Task 10.
2. Editing a transaction to reduce amount below Σ splits must be rejected, not saved (Task 5 form VM test).
3. Partial settlement then deleting the oldest transaction: FIFO age must shift to next outstanding debt (Task 2 balance test `fifo after debt removed`).
4. Import of malformed / wrong-format JSON must leave existing data intact (Task 3 backup test `invalid import keeps data`).
5. Friend renamed to an existing name (case/diacritic variant) must be rejected (Task 3 friend repo test).

## Phase 2: Quick input

### Task 10: Parser

**Files:** `src/domain/parser.ts`, `src/domain/parser.test.ts`

- `parse(input: string, friends: Friend[], today?: Date): ParseResult | ParseError`.
- `ParseResult = { ok: true; type; amount; note; category; date; splits: { friendName; friendId?; amount }[]; myShare; newFriendNames: string[] }`; `ParseError = { ok: false; code: 'empty' | 'noAmount' | 'zeroAmount' | 'multipleAmounts' | 'invalidParts' | 'amountTooSmall' | 'payForAllWithoutMention' | 'invalidDate' }`.
- Tokenize on whitespace (commas trimmed). Token kinds: amount (`^\+?(\d+([.,]\d+)?)(k|tr(\d+)?)?$` with dot-thousands rule: `\d{1,3}(\.\d{3})+` plain = integer; decimal only before unit), `/N`, `cho`, `@name`, `#cat`, date (`hqua`, `hôm qua` (two tokens), `dd/mm`). Remaining tokens = note. Leading `+` = income. Bare < 1000 → ×1000. Duplicate mentions (normalized) collapse. Unknown `#cat` → ignore & auto-detect.
- **Tests:** every row of spec table, `35k`, `1.5tr`, `1,5tr`, `2tr5`, `35000`, `35.000`, `35`, `35K`, `1TR`, `+500k lương` (income, `thunhap`), no amount, `0k`, `cafe 35k 20k` → multipleAmounts, `@nam @Nam` dedupe, `@huy` matches "Huy", `@tuấn` matches "Tuấn"/"tuan", `/2 @A @B` → invalidParts, `hqua`, `hôm qua`, `12/10`, `#giaitri` override, unknown name → `newFriendNames`.
- [ ] Commit `feat(domain): quick input parser`
